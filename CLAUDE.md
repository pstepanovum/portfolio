# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Start dev server on 0.0.0.0:3000
npm run build    # Production build
npm run lint     # ESLint via Next.js config
npm run start    # Run production server
npm test         # node --test (via tsx) over tests/
```

Only the pure helpers in `tests/` have coverage; nothing else does.

## Architecture

**Stack:** Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS 3 + Framer Motion

**Routing:** All pages live in `/app` using the App Router. Every page component is marked `"use client"`.

**Content pattern:** Content comes from two places.

*Firestore-backed (edited through the dashboard or MCP):* projects, certifications, timeline entries, contact submissions, and dashboard settings. All access goes through `lib/firebase/portfolio-core.ts`, which is transport-agnostic — the dashboard API routes and the MCP server both call the same functions. Zod input schemas live in `lib/firebase/schemas.ts`.

*Authored in code:* skills, proficiency levels, tooling, and core values live in `lib/content/background.ts` as plain serializable objects. Pages map the `iconKey` field back to React icon components (`app/about/about-data.tsx`, `app/skills/skills-page-client.tsx`). Keep this module JSON-safe — the MCP server serves it directly.

**Every dashboard page must call `await requireAdminSession()` itself, first, before reading any data.** The `(dashboard)` layout's check does not protect a page: the App Router renders a layout and its page in parallel, so a layout redirect only changes the status code while the page still fetches its data and serializes it into the response. Pages that relied on the layout leaked contact submissions, connected account addresses, bank names, and the activity log to anonymous requests until this was fixed. Do not wrap the guard in `Promise.all` with a data fetch; await it on its own line. Client components that fetch nothing server-side are the only exception.

**Admin dashboard:** `/dashboard` behind Firebase Auth with an `admin` custom claim, a 12-hour `__Host-` session cookie, and a mandatory TOTP second factor (`lib/auth/totp.ts`, `lib/auth/mfa.ts`; secrets and hashed recovery codes in `adminSecurity/{uid}`, encrypted with `CONNECTIONS_ENCRYPTION_KEY`). `resolveAdminSession` in `lib/firebase/auth.ts` requires the second-factor cookie once enrolled; `middleware.ts` confines an un-enrolled session to `/dashboard/security`; `requireAdminRequest` closes every admin API until enrollment. Sign-out revokes all Firebase sessions. Lost authenticator: recovery codes, or delete `adminSecurity/{uid}` with the Admin SDK. Enrollment is refused while an authenticator is enrolled, because enrollment needs no current code and would otherwise let a hijacked session swap in its own; replacing one goes through turning it off, which does. `verifySecondFactor` runs as a single Firestore transaction and accepts only a TOTP step strictly newer than the last one used. Approving an OAuth connection and connecting a Google account or custom MCP server also require an enrolled second factor.

**Firestore and Storage rules deny every client SDK, admin claim or not.** Nothing in the browser reads Firestore or writes Storage; the public site and the dashboard go through the server's Admin SDK, which ignores rules. The `admin` claim sits on the plain ID token issued after the password alone, so any rule granting it would let a stolen password skip the second factor. Only public Storage reads for site images stay open.

**MCP server:** `app/api/mcp/route.ts` exposes the portfolio over the Model Context Protocol (Streamable HTTP, stateless, JSON responses — Cloud Run gives no instance affinity, so no session state may live in memory). Tools are registered in `lib/mcp/` and gated by scope: `portfolio:read` always, `portfolio:write` only when granted.

**Apps MCP server:** `app/api/mcp/apps/route.ts` is a second, separate MCP resource exposing the Gmail accounts connected on the dashboard (`lib/mcp/admin-server.ts`; tools in `lib/mcp/tools/gmail.ts` for mail and drafts, `gmail-settings.ts` for labels, filters, vacation, send-as, IMAP/POP, forwarding, and push watch, with the shared `withAccount` wrapper in `gmail-shared.ts`). Tools take an `account` parameter (alias, email, or id) resolved by `lib/connections/store.ts`; it is optional only when exactly one account is connected. Scopes are `gmail:read` / `gmail:write`, plus `google:read` / `google:write`, `mcp:tools`, and `finance:read`. `get_youtube_transcript` rides on `google:read` too (see YouTube transcripts below). Everything the dashboard connects lives behind this one connector; the portfolio server stays separate because it edits the site itself rather than a connected account.

**Apps dashboard:** `/dashboard/connections` is the Composio-style apps overview: an activity heatmap and streaks (`lib/mcp/activity.ts`, fed by `withActivityLogging`, a Proxy around `McpServer.registerTool` that times and logs every tool call on both servers into the `activity` collection), the apps grid, and recent activity. `/dashboard/connections/gmail` is the Gmail app view with connected accounts and the "Available tools" list, which is generated from the real registration functions via `lib/mcp/tool-catalog.ts` so it cannot drift. `/dashboard/connections/custom/[id]` shows a registered custom MCP server, and `/dashboard/connections/youtube` shows the transcript tool with its cache and refusal counts.

**Mobile apps (friend codes):** `/dashboard/apps` lists the owner's apps (`lib/apps/registry.ts`: Margin, Nibble, Heft) and `/dashboard/apps/[app]` manages each one's friend codes, which grant complimentary Plus. Codes live in the app's own Firestore; `lib/apps/codes-client.ts` calls the app's `/api/admin/codes` with `MARGIN_ADMIN_SECRET` / `NIBBLE_ADMIN_SECRET` / `HEFT_ADMIN_SECRET` (copies of each app's Cloud Run `cron-secret`, Secret Manager secrets in `apphosting.yaml`). Nibble and Heft share one Firebase project, so they share the account, Plus, and the `friendCodes` collection itself: both pages list the same codes, and either share link turns Plus on in both apps (`sharesCodesWith` in the registry says so on the page). The routes under `app/api/admin/apps/[app]/codes` go through `requireAppAdmin` (`lib/apps/http.ts`), which requires a satisfied second factor, since a code hands out a paid feature. Every code carries a duration in whole days (7 days, 1, 3, 6 or 12 months, or a custom number up to `MAX_CODE_DURATION_DAYS` = 730), a redeem-by date, and a redemption limit; the grant it writes ends when the period is over, and there is no lifetime choice anywhere, in the form, the dashboard API, or the apps. Codes are redeemed only on each app's website at `/redeem`, never in the apps, because App Store and Play rules forbid unlocking features with in-app codes; the apps' Settings only open that page in the browser and re-read Plus on the way back.

**Custom MCP servers:** `lib/connections/custom-mcp.ts` registers a remote Streamable HTTP MCP server (auth: none, bearer, or OAuth 2.1 — for OAuth the admin server acts as the SDK's `OAuthClientProvider`, `lib/connections/mcp-oauth.ts`, persisting registration, tokens, PKCE verifier, and discovery state encrypted on the server's document; callback at `/api/admin/custom-mcp/oauth/callback`; a rejected grant flips the server to `reauth`; when the remote advertises `client_id_metadata_document_supported` instead of a registration endpoint the client id is the public Client ID Metadata Document at `/api/oauth/client-metadata`, SEP-991, which only works on an https origin), discovers its tools with the SDK client at registration time and stores them gzipped in a bytes field (`toolsGz`, `lib/connections/custom-mcp-tools.ts`, covered by `tests/custom-mcp-tools.test.ts`; Firestore caps a field and a document at 1 MiB, and a plain JSON string overflowed it at Swendl's 304 tools; old records with `toolsJson` still read and are rewritten on the next refresh), and proxies calls on demand. `lib/mcp/tools/custom.ts` exposes each as `<slug>__<tool>` under the `mcp:tools` scope, converting the remote's JSON Schema with `z.fromJSONSchema` so arguments are validated before the proxy hop. `pattern`, `patternProperties`, and `format` are stripped from remote schemas first: Zod runs a remote's regex on this server, and a catastrophic one froze the whole process, public site included. Each tool registers in isolation and duplicate names are skipped, since the SDK throws on a duplicate and one bad remote used to fail every request on the apps connector. Collection: `customMcpServers`. `lib/connections/marketplace.ts` lists remote servers with a known address (Luma, Robinhood, and placeholders for services without an MCP server) so the Apps page can register one with a click through the same create route; a marketplace entry is matched to its custom server by endpoint URL.

**Banks (Plaid):** bank tools (`lib/mcp/tools/plaid.ts`) are registered on the apps server behind the `finance:read` scope, which is never in `defaultScopes`, so a connector must ask for it by name and it has to be approved at the consent screen. They are read-only throughout: there are no write tools and no write scope, and the Transfer and Payment Initiation products are never requested, so nothing can move money. `/dashboard/connections/plaid` runs Plaid Link (`lib/connections/plaid.ts`, no SDK; `components/admin/plaid-link.tsx` loads Link from Plaid's CDN). The link token is minted at `/api/admin/plaid/link-token` and the public token is exchanged server-side at `/api/admin/plaid/exchange`; access tokens are stored AES-256-GCM encrypted in the `plaidItems` collection (`lib/connections/plaid-store.ts`). OAuth banks return the browser to `/dashboard/connections/plaid/oauth`, which re-opens Link with the original token held in sessionStorage; that URL must be registered verbatim under Allowed redirect URIs in the Plaid dashboard. **No transaction history is stored**: tools query Plaid live per call, so the only thing at rest is the encrypted credential. `/api/plaid/webhook` accepts item webhooks and verifies Plaid's ES256 JWT signature and body digest (`lib/connections/plaid-webhook.ts`) before flipping an item to `reauth` or `error`. Requires `PLAID_CLIENT_ID`, `PLAID_SECRET`, and `PLAID_ENV` (`sandbox` or `production`); without them the app degrades to a "not configured" notice. Production uses a different `PLAID_SECRET` than Sandbox while the client id stays the same. Access tokens do not cross environments, so each item records the `environment` it was linked under and `isFromAnotherEnvironment` turns a post-switch failure into "unlink and link again" instead of Plaid's bare invalid-token error. Only the `transactions` product is requested, with `investments` and `liabilities` optional; `auth` is deliberately omitted because it returns account and routing numbers. Link asks for 730 days of transaction history (`PLAID_TRANSACTIONS_DAYS_REQUESTED`, Plaid's maximum; its default is 90); the window is fixed when a bank is linked, so a bank linked under a smaller one must be unlinked and linked again to reach further back. `get_bank_overview` reads every linked bank in one call and totals cash, investments, and debt per currency (`lib/connections/plaid-overview.ts`, covered by `tests/plaid-overview.test.ts`); a bank that fails is listed under `unavailable` rather than failing the whole call.

**YouTube transcripts:** `get_youtube_transcript` (`lib/mcp/tools/youtube.ts`) turns a YouTube link into text. It sits on the apps server behind `google:read`, because fetching a caption track is a read and the only part that touches the owner's own data is the Drive save, which additionally requires `google:write`; no new scope was added, and without `google:write` the tool still answers and says plainly that nothing was filed. Nothing about it is reachable without the connector's OAuth: it is a tool on the authenticated endpoint, with no route of its own. Pure parts live in `lib/youtube/video-url.ts` (every URL shape, plus a bare id) and `lib/youtube/transcript-text.ts` (cue merging into paragraphs, auto-caption stutter collapse, `[Music]`-style noise stripping, timestamps, chapters from the description using YouTube's own rule of three-plus timestamps starting at 0:00, the cache key, and the Drive file name); both are covered by `tests/youtube.test.ts`, run with `npm test` (`node --test` through tsx; there is still no runner for anything else). Fetching is `lib/youtube/innertube.ts`: no binary, no Python, no yt-dlp. The caption list comes from YouTube's own player endpoint, tried as several client identities with the headset client (`ANDROID_VR`) first, because the plain WEB and ANDROID players now answer `UNPLAYABLE` ("the page needs to be reloaded") or `FAILED_PRECONDITION` to anything that cannot produce a proof-of-origin token, which needs YouTube's attestation VM; the public player key goes in the `X-Goog-Api-Key` header, since the old `?key=` form is refused. The watch page is the last resort, scraped for `ytInitialPlayerResponse` by balanced-brace scanning. Cues come from the signed `timedtext` URL that response carries, as json3 with srv3 XML (and the legacy `<text start=>` form) as fallbacks; `fmt` is replaced rather than appended, or the URL's own `fmt=srv3` wins. **A refusal must never read as a video without captions.** "Sign in to confirm you're not a bot" and an empty caption body are both rate limiting on this server's shared address, so they come back as a typed `blocked` error saying to try again in a few minutes, never as an empty file; only a player that got through and found no tracks yields `no_captions`. Successful fetches are cached in `youtubeTranscripts`, keyed by video id and the language asked for, with the cue list gzipped into one document (skipped above 850 KB, since Firestore caps a document at 1 MiB) and an alias document pointing an unspecified language at the resolved one. Per-day counters in `youtubeTranscriptStats` record every hit, fetch and refusal, including the ones that never reach a tool result, and `/dashboard/connections/youtube` shows them beside the generated tool list. By default only the first 2000 characters come back inline and the full .txt is written to a "YouTube transcripts" folder in the connected account's Drive (`lib/youtube/drive.ts`, reusing a file of the same name rather than piling up duplicates); `inline_chars` moves that line and `save_to_drive: false` keeps a short video in the chat. Deliberately one video at a time: no bulk mode, no queue, no public route.

**Google apps:** one Google account connection serves Gmail, Calendar, Drive, Sheets, Docs, Tasks, and Slides (`lib/connections/google-apps.ts`; pages at `/dashboard/connections/[app]`; API clients `calendar.ts`, `drive.ts`, `sheets.ts`, `docs.ts`, `tasks.ts`, `slides.ts` on the shared `google-api.ts`; tools in `lib/mcp/tools/google-workspace.ts` under `google:read` / `google:write`). Adding a scope flags existing connections `needsReconsent`.

**Connections (Google OAuth):** `/dashboard/connections/gmail` runs Google's OAuth code flow directly against a self-owned OAuth client (`lib/connections/google.ts`; the 12-scope set from Composio's Gmail consent screen: `https://mail.google.com/`, both `gmail.settings.*` scopes, identity, contacts, other contacts, and the People API self-profile scopes; contact tools use `lib/connections/people.ts`). Refresh tokens are stored AES-256-GCM encrypted in the `connections` collection (`lib/connections/crypto.ts`); the connect flow binds an encrypted `state` to a cookie nonce (`lib/connections/state.ts`). Requires `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, and `CONNECTIONS_ENCRYPTION_KEY` (`openssl rand -base64 32`). While the Google consent screen is in Testing status, refresh tokens expire after 7 days: `getAccessTokenForConnection` flips the record to `expired` on `invalid_grant` and the dashboard offers Reconnect. The Gmail REST client is `lib/connections/gmail.ts`; no Google SDK is used.

**OAuth 2.1:** The app is its own authorization server for two resources, `/api/mcp` (portfolio) and `/api/mcp/apps` (`MCP_RESOURCES` in `lib/oauth/config.ts`; `/api/mcp/admin` answers 410 with the new URL). Tokens are audience-bound to one resource and scopes are validated per resource; discovery for non-root resources is path-suffixed (`/.well-known/oauth-protected-resource/api/mcp/apps`), forwarded to the handler as `?resource=` by the rewrite. Opaque tokens are stored as SHA-256 digests in Firestore (`oauthClients`, `oauthCodes`, `oauthTokens`, plus `oauthGrants`), so a leak exposes no usable credential and revocation is immediate. `rotateRefreshToken` redeems and reissues in one transaction that reads the grant, and keeps a redeemed token as a `refresh_rotated` tombstone: presenting one after a 30-second grace window revokes the whole grant (RFC 9700 reuse detection), while a retry inside it reissues so a lost response never disconnects a client. Grants end at 180 days regardless of refreshing. Revocation marks the grant before deleting tokens so a racing refresh is refused; grants predating grant records get one on first refresh. Tokens with no `resource` are refused by the audience check. Dynamic client registration is open, but no token can be minted without an admin sign-in at the consent screen (`app/oauth/authorize`). Because anyone can register any name, a client that claims a known product must redirect to that product's own domain (`lib/oauth/client-identity.ts`: Claude to claude.ai, ChatGPT to chatgpt.com, Muse to meta.ai; loopback always allowed), enforced at registration, at authorization, and for hand-issued ids, after normalising Cyrillic lookalikes, zero-width characters, and bidi overrides. The consent screen leads with where the code goes, and authorization errors redirect only for a signed-in owner so the endpoint cannot be used as an open redirect. Apps that cannot register themselves get a client id issued by hand from the Client IDs panel on any server page (`components/admin/oauth-clients.tsx`, `/api/admin/oauth-clients`); a client id is public and carries no secret, so what binds an app is its redirect URI, which `validateAuthorizeParams` matches exactly. PKCE S256 is mandatory. A client that names no `resource` (RFC 8707) would otherwise fall through to the portfolio server and receive a token every other server refuses, so the consent screen asks which server instead of guessing (`components/admin/authorize-form.tsx`). The same screen lists every scope the chosen server can grant with the requested ones ticked, so the owner can widen or narrow what a client asked for rather than having to rebuild the client; the posted choice and scopes are re-validated server-side like every other parameter, and `normalizeScopes` drops anything the resource does not grant. Discovery metadata is served through `/.well-known/*` rewrites in `next.config.ts` — the App Router skips dot-prefixed directories, so these cannot be plain route folders. Set `OAUTH_ISSUER` to override the issuer origin on preview or custom domains.

**Component organization:**
- `components/` — shared layout components (Navbar, Footer, Container, ThemeToggle)
- `components/page/<route>/` — components scoped to a single page (e.g. `ProjectModal`, `SkillCard`)
- `components/ui/` — low-level UI primitives
- `lib/utils.ts` — exports `cn()` (clsx + tailwind-merge); use this for all className composition

**Styling:**
- Tailwind utility classes are primary. All custom design tokens live as CSS variables in `app/globals.css` (font scale, colors, transitions, typography).
- Custom **Realtime** font family (weights 300–900) loaded from `public/fonts/`. Geist Sans/Mono loaded via `next/font/google`.
- Theme toggle switches between light/dark via CSS variable overrides.

**Animations:** Framer Motion is used for entrance animations (fade-in, stagger) on the Hero section. CSS `@keyframes` handle simpler transitions (fadeInUp, fadeOutUp).

**Modals:** `ProjectModal` in `components/page/projects/` uses Radix UI dialog (`@radix-ui/react-dialog`).

**Images:** Next.js image optimization is disabled (`unoptimized: true` in `next.config.ts`). Images are served from `public/images/` as static assets.

**Deployment:** Firebase App Hosting / Next.js server deployment. Path alias `@/*` maps to the repo root.

**Scripts:** `npm run firebase:seed` seeds Firestore from `lib/content/defaults.ts`; `npm run firebase:create-admin` provisions the admin user. Scripts that import modules marked `server-only` must run as `npx tsx --conditions=react-server`.
